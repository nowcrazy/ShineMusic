# 产品与仓库概览

Shine Music 是一套**自建曲库**的音乐应用：不接第三方流媒体平台，面向个位数用户、单台服务器、局域网或自建域名。客户端以 **Android 为首发目标**，在 uni-app 里为 HarmonyOS NEXT 留了打包位。前后端同仓、目录隔离、分别部署。

## 产品原则

- **匿名可听、登录才互动**：已发布曲库浏览与 Range 播放默认可匿名；收藏、歌单、点歌、上传、消息需要登录。
- **邀请制**：关闭公开注册。第一位管理员用 `--create-admin` 在本机创建；之后用户只能凭管理员邮件邀请注册。
- **管理员控源**：正式曲库只进经过隔离、解析、转码和人工审核的音频。普通用户不能删曲、不能改角色、不能碰隔离文件。
- **用户上传是私有曲库，不是投稿直达公库**：登录用户可上传本地音频，处理完成后立刻对自己可听；是否进入公共曲库仍由管理员审核。
- **单机模块化单体**：当前是 ASP.NET Core + SQLite + 本地磁盘。没有 Redis、微服务或对象存储；出现并发/异地需求再评估。

## 仓库结构

```
ShineMusic/
  config/hosts.json          # 前后端唯一的地址配置源
  data/                      # 本地 SQLite、正式曲库、隔离区（不提交）
  frontend/                  # uni-app + Vue 3 客户端
  backend/ShineMusic.Api/    # .NET 10 Web API
  backend/api-list.md        # HTTP 接口清单
  backend/domain-contract.md # DTO / 枚举 / 安全约定
  docs/                      # 本目录：实现理解
```

前端脚本统一在 `frontend/` 目录执行（`yarn dev:h5` / `yarn build:h5` / `yarn typecheck`）。后端独立用 `dotnet run --project backend/ShineMusic.Api`。

## 角色

- **匿名听众**：浏览已发布内容、播放（`AnonymousPlayback` 开启时）。
- **登录用户（`user`）**：收藏、歌单、点歌投票、上传私有曲库、消息、推荐个性化。
- **管理员（`admin`）**：邀请、导入审核、曲库/精选维护、需求处理、存储审计清理。首个管理员不走公网注册。

## 配置与契约从哪里读

- 局域网 IP、前后端口、生产域名：**只改** `config/hosts.json`
- 功能开关、存储路径、上传/转码/歌词/点歌归档：`backend/ShineMusic.Api/appsettings.json`（可用环境变量覆盖）
- JWT 签名密钥、SMTP 密码：**不进仓库**，用 User Secrets 或环境变量
- 前后端 DTO：后端 `Contracts/` 为源，Python 脚本生成 `api.generated.ts`
