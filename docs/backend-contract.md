# 后端接口约定

本文保留客户端对服务端的概览。首版的权威接口清单是 [backend/api-list.md](../backend/api-list.md)，全局 DTO、枚举、错误格式和配置约束见 [backend/domain-contract.md](../backend/domain-contract.md)。客户端通过 `VITE_API_BASE_URL` 配置服务地址，API 前缀为 `/api/v1`；健康检查为 `GET /health`。

首版范围包括匿名曲库浏览与播放、管理员邀请注册、登录后的收藏/歌单/歌曲需求与投票，以及管理员本机批量导入、隔离审核、AAC/M4A 转码和发布。当前后端已实现这些读写流程；首版不开放普通用户音频投稿，不依赖第三方音乐平台，聆听事件和个性化推荐后置。

## 后续能力，不属于首版

- **聆听行为**：未来可批量接收播放、完成、跳过等事件；需先确定隐私告知、保留期限、匿名标识和限流策略。
- **用户投稿与对象存储**：未来若开放用户投稿，再设计版权声明、上传意向、恶意文件扫描、对象存储和审核流程。旧草案中的 `upload-intent`、`submissions` 和对象 key 不代表首版 API。

首版播放由服务端管理媒体文件并支持 HTTP Range；不向客户端返回物理路径或存储凭据。部署前需配置访问控制，不能把开发服务直接暴露到公网。
