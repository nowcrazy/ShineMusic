# 修复目标

以网易歌单 `900025217` 的216首快照为固定基线，修复已证实的单字名称误拒、歌词版本错配与时间轴越界，改善原平台字段/歌词利用，并补足下载失败诊断和队列并发验证。保留已有未提交改动；不提交、不部署，不批量修改历史人工元数据。

## 1. 修复统一身份匹配器

修改 `ShineMusicApi/ShineMusic.Service/Media/SourceDownload/TrackIdentityMatcher.cs`。

- 将“至少两个字符”改为“规范化后非空且精确匹配”；单字歌名仍须通过艺人、版本与已知时长检查，不使用子串匹配自动放行。
- 艺人名称不再直接复用去除歌曲版本装饰的规则；保留艺人括号名称，避免把“烟(许佳豪)”降为“烟”并误匹配其他艺人。
- 保持原标题与候选版本一致时允许Live等用户明确选择的版本；不同版本拒绝或待审。
- 将Club Mix、变速等本次真实失败的版本标记纳入明确规则，未知修饰继续待审，不普遍删除括号内容。
- 新增 `ShineMusicApi/ShineMusic.Tests/Metadata/TrackIdentityRegressionTests.cs`：覆盖6首误拒样本、单字不同艺人、空标题、版本差异和时长异常。

## 2. 歌词改为先校验，再排序

修改 `Metadata/Lyrics/ExternalLyricsProviders.cs`、`Metadata/LyricsResolver.cs`，新增共享 `Metadata/Lyrics/LyricsValidation.cs`（均位于Service项目）。

- LRCLIB精确接口与搜索接口、酷狗、咪咕统一复用身份匹配器；评分仅用于已通过身份校验的候选排序，不能抵消版本或时长错误。
- 已知目标时长时，候选时长差大于5秒不得自动采用；缺少必要身份或时长信息的跨源候选标为未确认并继续兜底。
- LRCLIB精确接口也验证返回身份，不直接将HTTP命中标为置信度1.0；分数不表述为准确率。
- 校验LRC多时间戳与offset，拒绝无效时间戳及有效时间戳超过音频时长5秒的结果；不要求末句必须贴近音频结尾，不盲目裁剪或缩放歌词。
- 无效候选继续尝试同源下一候选和下一来源，设候选数/请求预算；避免第一份错误歌词阻断后续正确结果。
- 外部结果保留候选ID与拒绝原因；诊断区分无结果、身份不符、版本不符、时长不符、时间轴越界、源不可用。保持现有调用兼容，人工歌词锁不变。
- 修复调用者取消被通用异常捕获的问题；单源超时可兜底，调用者取消立即传播。
- 新增受控HTTP测试，固定《爱情陷阱》《Stronger》《风的季节》《感谢你曾来过》与3首时间轴异常；验证拒绝后仍能选择后续有效候选。

## 3. 优先利用原平台身份与数据

修改 `LyricsQuery`及其调用点 `Media/LibraryImportJob.cs`；新增 `Metadata/Lyrics/NeteaseLyricsProvider.cs`，在 `Api/Extensions/ModuleRegistrations.cs`注册。

- 将可信原平台名称和歌曲ID传入歌词查询；先验证匿名网易按ID取歌词端点，用本歌单真实样本确认后接入。保留内嵌、旁挂优先级，网易同ID查询优先于跨源搜索。
- 同ID歌词仍检查时间轴；纯音乐、无歌词、无时间轴文本分别记录，不把“无歌词”标记文本当歌词成功。
- 端点不可用时保留明确失败证据并走现有外部链，不承诺所有歌曲有歌词。
- 检查 `Media/SourceDownload/SourceDownloadJob.cs`、`Metadata/ImportMetadataEnricher.cs`、网易适配器的字段传递：原平台已经提供且身份确认的封面、发行信息优先保留并标注来源；只有缺失字段再请求外源。
- 检查网易原始响应是否确实提供完整日期等字段；有可靠语义才映射，不从年份推造日期，不从歌名猜流派。不以放松iTunes专辑/版本限制来追求命中率；本阶段不承诺解决所有跨平台目录差异。

## 4. 下载失败诊断与并发验证

修改 `tools/PlaylistProbe/ChainProbe.cs`及README；按诊断结果有针对性调整 `Media/SourceDownload/NeteaseSourceProvider.cs`，不无证据扩展下载端点。

- 对《九张机》记录候选解析各阶段的安全错误码、HTTP状态、候选数、超时/空地址/无权限等可观察结果；不输出Cookie、歌词正文或签名URL。无法确认原因时明确标未知，不能直接归咎版权。
- 探测器记录实际传输起止与峰值、任务耗时、失败阶段，并进行同组样本并发1与3的有界对照。保持生产下载并发2、转码1配置。
- 校验成功音频的完整解码、时长、编码和码率；失败不计成功。FLAC仅作为编码结果，不宣称原生无损。
- 对 `Tasks/QueueConsumers.cs`、`Infrastructure/Messaging/RabbitMessageBus.cs`使用隔离测试队列验证并发上限、单条失败及重投递；不向正式业务队列投入216首任务。报告区分队列机制验证与实际歌曲入库全链路验证。

## 完成标准与边界

完成标准是确定性缺陷得到测试覆盖并修复、真实样本中的错误候选不再被自动采用、每个未完成条目有可追踪原因。元数据来源缺字段、平台不可下载和歌词未确认可以作为明确剩余缺口，不能伪装成成功。本方案不自动重写历史已发布歌词，不执行216首批量发布；需要历史修复时另行按来源与人工锁制定迁移。
